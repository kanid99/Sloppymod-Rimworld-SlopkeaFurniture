# Working on this repo

## The default branch is the release

The owner installs and updates the SloppyMods mods straight from GitHub: RimSort
clones this repository's default branch (`main`) into RimWorld's Mods folder and
pulls it in place, so every commit on `main` is what the game loads next.

- **Push every change to `main`** as soon as it is done. This is the owner's
  standing instruction: no asking first, no leaving work on a branch. Work on a
  branch if the session requires one, then merge it into `main` and push.
- **Snapshot every build on its own branch.** Every commit gets a build number
  (below). Push the same commit to `main` AND to a branch named after the build,
  so any build can be restored:

      git push origin HEAD:main HEAD:refs/heads/build/0.9.N

  Build branches are restore points: never move or delete one. To roll back,
  reset `main` to an earlier `build/...` branch - only when the owner asks.
- **Stamp the build number before every commit**: `<modVersion>` in
  `About/About.xml` and a `Build x.y` line at the top of its description, set to
  `0.9.<commit count after this commit>` (`git rev-list --count HEAD` + 1; needs
  a full, not shallow, clone). The branch name uses the same number.
- Each commit must load and play as-is: nothing half-done.
- **Commit the compiled assembly** (`1.6/Assemblies/SlopkeaFurniture.dll`).
  RimWorld loads the DLL, not the source. Rebuild it
  (`dotnet build -c Release` in `Source/SlopkeaFurniture/`) and commit it in the
  same commit as any C# change.
- Keep `packageId` unchanged: saves and RimSort key on it.

## Art

- Art is generated by `Source/Art/` (see its README). After any art change run
  `python3 Source/Art/draw_sprites.py` and `python3 Source/Art/verify_art.py`.
- For art changes, show the owner before/after comparisons - but they ship to
  `main` like any other change; the build branch is the way back.
